## 本次核心结论

当前项目已经具备可演示闭环，但要走向“可信的 AI 面试产品”，下一步重点不是继续堆功能，而是提升过程质量：

1. 上传、权限和数据隔离要可靠。
2. 项目题必须绑定简历证据。
3. 问题要从“多子问题堆叠”升级为“主问题 + 动态追问”。
4. 面试要从静态题目列表升级为有状态的 topic/turn/decision 流程。
5. 严厉模式用于测水平，教练模式用于练提升。
6. 分类、评分、趋势和训练计划必须基于稳定枚举和可解释数据。

## 建议实施顺序

1. 继续验证上传去重修复，确保不同用户可上传同一份简历。
2. 按数据库设计新增 `InterviewTopic`、`InterviewTurn` 和相关枚举。
3. 落地 Topic Registry 第一版，先覆盖前端、后端、Java/Python、AI Agent、LLM 应用和微调强化学习。
4. 将现有题目生成结构升级为 `main_question + followup_goals + evidence_snippet`。
5. 实现动态报告和“明日 3 件事”训练任务生成规则。
6. 增加 JD 结构化和策略生成，让 JD 影响 topic 权重、题型配比、追问方向和训练优先级。
7. 将动态面试生成流程改为首题优先，并增加缓存、状态、超时兜底和成本观测。
8. 将 RAG 接入讲解层和训练资料推荐，但不接入评分裁判链路。
9. 优先实现教练模式的“提示后同题重答”闭环。
10. 再实现严厉模式的连续追问。
11. 建立质量基准与测试报告可信化流程，覆盖出题、追问、评分、教练提升和 RAG 讲解。
12. 最后补跨 session topic 去重和动态面试质量基准自动化。
