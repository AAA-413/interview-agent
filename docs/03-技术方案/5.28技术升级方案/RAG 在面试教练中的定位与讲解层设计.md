# RAG 在面试教练中的定位与讲解层设计

文档日期：2026-05-28

## 1. 核心定位

RAG 不应该参与模拟面试评分的裁判权，但应该参与学习、讲解、复盘和资料推荐。

边界：

```text
评分：看题目、用户回答、评分标准、项目证据、JD 要求
讲解：可以用知识库增强
训练推荐：可以用知识库补资料
```

一句话：

```text
不要让 RAG 当裁判，让 RAG 当教练资料助手。
```

## 2. 为什么不让 RAG 参与评分

如果评分依赖知识库，知识库质量会污染面试结果：

- 用户知识库资料不全，系统可能低估回答。
- 用户上传低质量博客，系统可能错误扣分。
- 不同用户知识库不同，同一回答得分不一致。
- RAG 检索漏召回，评分不稳定。

因此，模拟面试评分主要依赖：

```text
题目
用户回答
参考评分标准
项目证据
JD 要求
```

知识库不直接决定候选人答得好不好。

## 3. 用户“会问”的环节放在哪里

用户会问的典型问题：

```text
为什么我这个回答不够好？
这个知识点正确答案是什么？
我应该看什么资料？
能不能给我一个学习路径？
```

这些问题不应该放在评分前，也不应该打断面试过程。

推荐放在三个位置：

### 3.1 报告页 Topic 详情卡片

每个 topic 卡片下提供入口：

```text
问教练
查看讲解
推荐资料
生成学习路径
```

适合问题：

- 为什么这个 topic 得分低？
- 我这个回答缺了哪些关键点？
- 这个 topic 应该怎么补？

### 3.2 单轮回答复盘区

每个 turn 的反馈后提供入口：

```text
解释这次扣分
查看参考讲解
用我的知识库补课
```

适合问题：

- 为什么这句话不够好？
- 追问里问的概念是什么？
- 我应该如何改写这一段回答？

### 3.3 训练任务详情页

训练任务下提供入口：

```text
相关资料
学习路径
再练一次
```

适合问题：

- 做这个任务前，我该先看什么？
- 有没有我知识库里的资料？
- 这个任务如何分步骤完成？

不建议放在：

- 面试进行中的实时评分链路。
- 创建题目的主链路。
- 最终分数计算链路。

## 4. 知识库没有资料时是否强行找

不强行找。

检索必须有置信度和引用门槛。没有足够命中时，应明确告诉用户：

```text
你的个人知识库暂未找到足够相关资料。
```

然后再按层级 fallback：

```text
个人知识库
  -> 系统默认知识库
  -> 模型通用讲解
```

但每一层都要明确标记来源。

### 4.1 推荐策略

```text
个人知识库高置信命中：
  使用个人资料讲解，并展示引用。

个人知识库无命中，系统默认知识库命中：
  使用系统默认资料讲解，并提示“未在你的知识库中找到，以下来自系统资料”。

个人知识库和系统默认知识库都无命中：
  使用模型通用讲解，并提示“未引用知识库资料”。
```

### 4.2 禁止行为

不要：

- 明明没检索到资料，却假装来自知识库。
- 为了凑引用，强行拿低相关片段。
- 把 RAG 低置信结果写进评分理由。
- 把“知识库没有”包装成用户能力差。

## 5. 检索命中状态

建议定义讲解来源状态：

```text
PERSONAL_KB_HIT
SYSTEM_KB_HIT
NO_KB_HIT
MIXED_HIT
```

字段：

```json
{
  "source_status": "PERSONAL_KB_HIT",
  "citations": [],
  "retrieval_confidence": 0.82,
  "fallback_reason": null
}
```

如果没有命中：

```json
{
  "source_status": "NO_KB_HIT",
  "citations": [],
  "retrieval_confidence": 0.0,
  "fallback_reason": "个人知识库和系统默认知识库均未找到高相关资料"
}
```

## 6. 检索触发时机

RAG 检索建议按需触发，而不是每次评分都自动触发。

触发入口：

- 用户点击“查看讲解”。
- 用户点击“推荐资料”。
- 用户点击训练任务详情。
- 系统生成学习路径时。

可选预取：

- 报告生成后，对 Top 3 风险 topic 异步预取资料。
- 预取失败不影响报告展示。

这样可以控制成本和延迟。

## 7. Topic Registry 与 RAG 的关系

Topic Registry 是能力地图，Knowledge Base 是学习资料库。

建议建立映射：

```text
topic_key -> retrieval_queries
```

示例：

```json
{
  "topic_key": "rag_multi_channel_retrieval",
  "retrieval_queries": [
    "RAG 多路召回 BM25 向量检索",
    "Cross-Encoder 重排序 召回评估",
    "Query Rewrite 检索增强"
  ]
}
```

训练任务可以根据 `topic_key` 自动生成检索 query。

## 8. 两层知识库

建议后续区分两层知识库：

### 8.1 用户个人知识库

来源：

- 用户上传的课程笔记。
- 项目文档。
- 面经。
- 博客。
- 公司资料。

特点：

- 个性化强。
- 质量不可控。
- 需要权限隔离。

### 8.2 系统默认知识库

来源：

- 平台维护的高质量知识文档。
- 标准面试知识。
- 技术专题讲解。

特点：

- 质量稳定。
- 可作为 fallback。
- 适合通用讲解和学习路径。

第一版如果没有系统默认知识库，也可以直接 fallback 到模型通用讲解，但必须标记：

```text
未引用知识库资料。
```

## 9. 讲解输出结构

用户点击“查看讲解”后，建议返回：

```json
{
  "topic_key": "function_calling_tool_calling",
  "question": "Function Calling 流程是什么？",
  "answer_issue": "用户回答把模型选择工具和真正执行接口混为一谈。",
  "explanation": "Function Calling 通常包含工具 schema 提供、模型选择工具和参数、业务侧执行工具、结果回传模型等步骤。",
  "citations": [],
  "source_status": "SYSTEM_KB_HIT",
  "study_steps": [
    "先理解工具 schema 的作用",
    "再区分模型输出 tool call 和业务侧执行工具",
    "最后练习一个带参数校验的工具调用例子"
  ],
  "next_practice": "用 1 分钟解释 Function Calling 的完整链路。"
}
```

## 10. 与训练任务的连接

训练任务中可展示资料推荐：

```text
任务：补齐 RAG 30% 提升的证明口径

相关资料：
- 你的知识库：RAG 检索评估笔记
- 系统资料：Recall@K、MRR、NDCG 指标说明

下一步：
- 写出 baseline、指标、测试集来源
- 再练一次 RAG 多通道检索 topic
```

如果无资料：

```text
你的知识库暂未找到相关资料。
系统将先提供通用讲解；建议后续补充 RAG 检索评估相关资料。
```

## 11. RAG 质量评估独立进行

RAG 质量不要混进模拟面试质量基准。

RAG 单独评估：

- 检索是否召回正确片段。
- 回答是否忠实引用。
- 无资料时是否承认不知道。
- 多知识库隔离是否正确。
- 查询改写是否真的提升召回。
- fallback 是否标记清楚。

模拟面试单独评估：

- 题目是否好。
- 追问是否准。
- 评分是否稳。
- 反馈是否能训练。

## 12. 实施建议

第一版：

1. 在报告页 topic 卡片增加“查看讲解/推荐资料”入口。
2. 点击后按需检索个人知识库。
3. 无高置信命中时，不强行引用，直接返回 `NO_KB_HIT`。
4. 用模型通用知识生成讲解，但明确标记“未引用知识库资料”。
5. 训练任务详情页复用同一套讲解和资料推荐接口。

第二版：

1. 增加系统默认知识库。
2. 增加 topic_key 到 retrieval_queries 的配置。
3. 对 Top 3 风险 topic 做异步资料预取。
4. 引入检索置信度和引用质量评分。

第三版：

1. 用用户学习行为优化资料推荐。
2. 根据训练任务自动推荐需要补充到知识库的资料类型。
3. 建立 RAG 质量基准集，输出真实可行的测试报告。
