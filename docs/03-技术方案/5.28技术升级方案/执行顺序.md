# 5.28 技术升级方案执行顺序

文档日期：2026-05-28

## 总原则

执行顺序按依赖关系排列，不按文档产生顺序排列。

核心路线：

```text
数据可信
  -> topic 稳定
  -> JD 策略稳定
  -> 动态面试数据模型
  -> 教练模式闭环
  -> 报告与训练任务
  -> RAG 讲解层
  -> 严厉模式
  -> 去重与质量基准
```

第一阶段目标不是一次性做完整动态面试官，而是先做一个可测试、可解释、可继续扩展的教练模式 MVP。

## Phase 1：Topic Registry MVP

### 目标

先稳定 `topic_key`，否则动态面试、topic 去重、趋势统计和训练计划都会继续混乱。

### 产出

1. 新增 `topic_registry` 模块。
2. 定义 `TopicDef`、`TopicPack`。
3. 落地第一版 topic pack：
   - `common_engineering`
   - `frontend`
   - `backend_common`
   - `java_backend`
   - `python_backend`
   - `database_cache_mq`
   - `ai_agent`
   - `llm_application`
   - `llm_finetuning_rl`
   - `system_design`
   - `fallback`
4. 实现规则版 topic normalizer：
   - 输入：`raw_topic`、`evidence_snippet`、`question_type`、`target_role/skill_id`
   - 输出：`topic_key`、`skill_key`、`label`、`confidence`、`fallback_reason`
5. 补单元测试：
   - RAG 能匹配到 `rag_multi_channel_retrieval`
   - MCP 能匹配到 `mcp_tool_integration`
   - Java Redis 缓存问题不会误匹配到 Agent memory
   - React 状态管理能进入 frontend pack
   - 低置信主题进入 fallback

### 暂缓

- embedding 相似度。
- LLM top3 裁决。
- 管理后台维护 topic registry。

### 目标

让 JD 影响面试策略，而不是只作为 prompt 附件。

### 产出

1. 新增 `StructuredJD` DTO。
2. 实现 `JDParseService`。
3. 输出：
   - `quality_score`
   - `role_domain`
   - `seniority`
   - `required_skills`
   - `preferred_skills`
   - `responsibilities`
   - `topic_weights`
   - `question_type_mix`
4. 实现低质量 JD 降权规则。
5. 将 JD-topic 映射接入 Topic Registry。
6. 为后续动态面试 plan 生成提供 `topic_weights`。

### 暂缓

- 多 JD 对比。
- JD embedding 匹配。
- JD 结构化缓存可在 Phase 6 和耗时优化一起做。

## Phase 4：Interview Plan 与主问题生成

### 目标

从“一次生成 8 道题”升级为“生成面试计划 + 第一题”。

### 产出

1. 新增 `InterviewPlanService`。
2. 输入：
   - resume profile
   - structured JD
   - topic registry
   - 历史 topic，可先不接
3. 输出：
   - 4 个 topic，教练模式第一版
   - `main_question`
   - `evidence_snippet`
   - `followup_goals`
   - `exit_criteria`
4. 固化题型配比：
   - 2 个 project
   - 1 个 knowledge
   - 1 个 system_design
5. 项目题必须绑定证据。
6. JD 有但简历没有的内容只能生成 knowledge 或 system_design。

### 暂缓

- 跨 session 去重。
- 多模式复杂策略。
- 自动生成完整追问。

## Phase 5：教练模式最小闭环

### 目标

优先实现最有产品价值的训练闭环：

```text
主问题 -> 首次回答 -> 诊断提示 -> 同题重答 -> 对比反馈
```

### 产出

1. 新增动态面试创建接口。
2. 新增提交 turn answer 接口。
3. 统一能力评分。
4. 生成 signals：
   - strengths
   - gaps
   - risks
5. `CoachInterviewPolicy` 决策：
   - `COACH_RETRY`
   - `NEXT_TOPIC`
   - `END`
6. 生成 coach hint。
7. 每个 topic 最多 2 次重答。
8. 记录：
   - `initial_score`
   - `retry_score`
   - `score_delta`

### 约束

教练提示只给结构、方向和缺口，不直接给完整答案。

### 暂缓

- 严厉模式连续追问。
- 语音。
- 实时打断。

## Phase 6：动态报告与“明日 3 件事”

### 目标

让面试结束后用户知道下一步练什么，而不是只看到分数和评语。

### 产出

1. 按 topic 汇总报告。
2. 输出题型分：
   - project
   - knowledge
   - system_design
3. 输出能力分：
   - authenticity
   - technical_depth
   - knowledge_accuracy
   - system_thinking
   - communication_structure
4. 生成 Top 3 risks。
5. 生成“明日 3 件事”。
6. 固化任务类型：
   - `RETRY_TOPIC`
   - `PROJECT_PROOF`
   - `FIX_RESUME_EVIDENCE`
   - `KNOWLEDGE_DRILL`
   - `SYSTEM_DESIGN_DRILL`
   - `EXPRESSION_REWRITE`

### 暂缓

- 完整 7 天计划。
- 复杂任务状态流。
- 自动资料预取。

### 关联文档

- [动态面试报告与训练任务生成规则](./动态面试报告与训练任务生成规则.md)

## Phase 7：生成耗时与等待体验优化

### 目标

让用户尽快看到第一题，并为后续异步化打基础。

### 产出

1. 创建动态面试时只生成 plan 和第一题。
2. 增加状态：
   - `PLANNING`
   - `INTERVIEWING`
   - `FAILED`
3. 前端展示生成阶段：
   - 分析简历项目
   - 匹配 JD 重点
   - 选择面试主题
   - 准备第一题
4. 增加失败兜底：
   - 评分失败不丢答案
   - 追问失败进入下一 topic 或规则追问
   - coach hint 失败用规则提示
5. 记录 LLM latency 和 token 成本。

### 暂缓

- SSE。
- 后台全异步 plan 生成。
- 自动预生成下一 topic。

### 关联文档

- [动态面试生成耗时与等待体验优化方案](./动态面试生成耗时与等待体验优化方案.md)

## Phase 8：RAG 讲解层与资料推荐

### 目标

把 RAG 放在解释层和训练资料推荐层，不进入评分裁判链路。

### 产出

1. 报告页 topic 卡片增加：
   - 查看讲解
   - 推荐资料
   - 生成学习路径
2. 单轮回答复盘区增加：
   - 解释扣分
   - 用我的知识库补课
3. 训练任务详情页增加资料推荐。
4. 检索命中状态：
   - `PERSONAL_KB_HIT`
   - `SYSTEM_KB_HIT`
   - `NO_KB_HIT`
   - `MIXED_HIT`
5. 无高置信命中时不强行引用。

### 暂缓

- 系统默认知识库大规模建设。
- 自动预取所有 topic 资料。
- RAG 质量自动报告。

## Phase 9：严厉模式

### 目标

实现压力测试和真实性验证。

### 产出

1. `StrictInterviewPolicy`。
2. 每个 topic：
   - 主问题
   - 最多 2 次追问
   - 换 topic
3. 不给提示。
4. 不允许重答。
5. 追问重点：
   - 个人职责
   - 实现细节
   - 指标口径
   - 异常处理
   - 技术取舍
6. 报告突出抗压漏洞。

## Phase 10：跨 session topic 去重与个人画像

### 目标

解决多轮面试重复偏高，让训练计划有连续性。

### 产出

1. 保存并查询历史 topic：
   - `topic_key`
   - `skill_key`
   - `question_type`
   - `evidence_hash`
   - `final_score`
2. 生成计划时读取最近 2 次或最近 7 天 topic。
3. 同 topic 降权或换角度。
4. 低分 topic 进入明确标记的同题再练。
5. 初步形成 user topic profile。

### 暂缓

- 复杂推荐算法。
- 组织/班级画像。

## Phase 11：质量基准与测试报告可信化

### 目标

从“能跑”升级为“可信、可回归、可对比”。

### 产出

1. 固化 5 份代表性简历样本。
2. 每份简历配固定 JD。
3. 每个 topic 准备 4 类回答：
   - 强回答
   - 普通回答
   - 空泛回答
   - 跑偏回答
4. 建立五条质量线：
   - 出题质量
   - 追问质量
   - 评分质量
   - 教练提升
   - RAG 讲解
5. 输出 `report.md` 和 `results.json`。
6. 加入人工抽检和版本对比。
