# AI 面试教练产品升级大纲

> 文档日期：2026-05-21
> 目标：将当前“智能 AI 面试官平台”升级为面向学生求职场景的“AI 面试教练”

---

## 一、产品定位升级

### 1.1 当前定位

当前项目已经具备较完整的技术底座：

- 简历解析与评分
- 模拟面试与追问
- 面试方向 Skill
- 知识库 RAG
- 知识图谱 GraphRAG
- 智能下载与 Agent 编排
- 用户认证、数据隔离、质量检查脚本

这些能力证明系统已经超过普通 Demo，但从用户视角看，当前更像一个“AI 面试工具箱”。

### 1.2 目标定位

升级后的产品应聚焦为：

> 帮助同学从“不知道怎么准备面试”，走到“每天知道练什么、怎么改、离目标岗位还差什么”的 AI 面试教练。

核心转变：

| 当前 | 升级后 |
|------|--------|
| 功能集合 | 成长闭环 |
| 模拟问答 | 个性化训练 |
| 打分报告 | 教练式纠偏 |
| 知识库系统 | 面试补弱系统 |
| 用户自己找入口 | 系统告诉用户下一步 |

---

## 二、目标用户与真实痛点

### 2.1 目标用户

第一阶段明确聚焦“校招/转岗”同学，暂不把 3-5 年以上社招作为主路径。

优先服务以下用户：

1. 应届生/实习生：缺少真实面试经验，不知道基础题、项目题要答到什么深度。
2. 转岗/自学同学：知识点碎片化，项目证据不足，不知道企业会如何追问。
3. 低年限求职者：有项目或实习经历，但讲不深、经不起连续追问。
4. 面试临近用户：时间紧，需要快速定位短板并形成 7 天冲刺计划。

暂不优先服务：

- 3-5 年以上社招工程师
- 管理岗/架构岗
- 企业招聘端面试官

### 2.2 用户核心痛点

| 痛点 | 用户表现 | 当前系统覆盖度 | 升级方向 |
|------|----------|----------------|----------|
| 不知道怎么准备 | 收藏大量资料但没有计划 | 部分覆盖 | 生成岗位诊断与 7 天计划 |
| 不知道自己差在哪 | 只知道答得不好，不知道原因 | 部分覆盖 | 弱点画像 + 可执行建议 |
| 简历项目讲不深 | 项目被追问就露怯 | 部分覆盖 | 项目深挖训练 |
| 缺少真实面试压迫感 | 练题会，面试不会说 | 部分覆盖 | 面试官 persona + 连续追问 |
| 反馈不够可执行 | 分数有了，但不知道怎么改 | 部分覆盖 | 60/80/90 分回答对比 |
| 知识补弱无路径 | 知识库里有资料，但不会用 | 部分覆盖 | 错题本 + 复训卡片 |
| 目标岗位不清晰 | Java/前端/算法准备重点混乱 | 较弱 | JD/公司/级别驱动训练 |

## 三、升级后的核心闭环

### 3.1 用户主路径

```text
上传简历 / 输入目标岗位 / 粘贴 JD
  ↓
生成面试诊断报告
  ↓
输出短板、风险追问、备考计划
  ↓
开始项目深挖 / 知识补弱 / 模拟面试
  ↓
获得教练式反馈和优化版回答
  ↓
沉淀错题、弱点和复训任务
  ↓
持续训练，更新通过概率和能力画像
```

### 3.2 产品北极星指标

建议北极星指标定义为：

> 用户完成一次诊断后，在 7 天内完成的有效训练次数。

辅助指标：

- 诊断完成率
- 模拟面试完成率
- 单题二次回答提升率
- 弱点复训完成率
- 7 日留存
- 用户主动上传简历/JD 数量
- 面试报告分享/导出次数

## 四、能力模块升级大纲

### 4.1 面试诊断首页

目标：让用户进入系统后立刻知道“我该练什么”。

输入：

- 简历
- 目标岗位
- 公司/级别
- JD（可选）
- 面试时间（可选）

输出：

- 当前面试通过概率
- 主要短板 Top 5
- 简历高风险追问
- 目标岗位知识缺口
- 7 天备考计划
- 今日训练任务

### 4.2 简历项目深挖

目标：把简历从“评分对象”升级为“面试训练素材”。

能力：

- 自动识别项目亮点和薄弱描述
- 生成项目真实性追问
- 生成技术深度追问
- 生成指标量化追问
- 给出项目讲述结构：背景、挑战、方案、结果、复盘

典型输出：

```text
你写了 Redis 缓存优化，但缺少：
1. 缓存击穿处理
2. 数据一致性方案
3. QPS/RT 优化指标
4. 为什么不用本地缓存

建议先训练 5 道项目深挖题。
```

### 4.3 教练式模拟面试

目标：从“问答系统”升级为“真实面试陪练”。

能力：

- 面试官 persona：温和、严格、项目深挖、大厂八股、校招基础
- 连续追问：围绕一次回答持续追问 1-3 层
- 卡壳处理：识别不会答、答偏、答浅
- 面试节奏：开场、自我介绍、技术题、项目题、反问环节

### 4.4 可执行反馈系统

目标：让用户知道“下一句该怎么改”。

反馈结构：

1. 面试官视角判断
2. 当前回答问题
3. 缺失知识点/项目细节
4. 推荐回答结构
5. 60 分/80 分/90 分回答对比
6. 下一道针对性训练题

### 4.5 弱点画像与错题复训

目标：把一次性练习变成持续成长系统。

能力：

- 自动归类弱点：原理、项目、表达、系统设计、算法、真实度
- 错题本：记录题目、原回答、反馈、优化回答
- 复训队列：根据遗忘曲线和低分点自动安排
- 能力雷达图：展示技能掌握变化

### 4.6 知识库能力产品化

目标：隐藏复杂技术词，前台表达成用户能理解的学习能力。

底层能力仍使用 RAG/GraphRAG/智能下载，但前台包装为：

- 面经整理器
- 博客转面试题
- JD 转训练计划
- 项目文档转追问题
- 高频题知识补弱
- 错题知识卡片

## 五、阶段优先级

### P0：面试诊断闭环

必须优先完成：

- 诊断首页
- 简历 + JD + 岗位输入
- 短板报告
- 今日训练任务
- 基础训练入口跳转

原因：这是产品从“工具箱”变成“教练”的关键。

### P1：项目深挖训练

重点完成：

- 从简历项目生成追问题
- 项目回答模板
- 项目真实性/技术深度评分
- 优化版回答生成

原因：项目深挖是学生面试最容易崩的环节，也是差异化最高的场景。

### P2：教练式反馈与复训

重点完成：

- 60/80/90 分回答对比
- 错题本
- 弱点标签
- 复训任务

原因：解决“知道错，但不知道怎么变好”的问题。

### P3：知识库产品化与增长

重点完成：

- 面经转题库
- 博客转知识卡
- 公司题库包
- 分享报告
- 训练日历

原因：提升内容供给、留存和传播。

---

## 六、产品原则

1. 少展示系统能力，多展示用户下一步。
2. 不直接说“RAG/GraphRAG”，而说“根据你的资料生成训练题”。
3. 不只给分数，要给可复制的改法。
4. 不让用户自己找资料，系统主动生成训练路径。
5. 每次训练都沉淀为弱点画像和下一次任务。
6. 面试训练必须围绕目标岗位和简历，而不是泛泛问答。

---

## 七、一句话总结

升级方向不是继续堆功能，而是把现有技术能力重新组织成一个清晰的用户成长闭环：

> 诊断短板 → 针对训练 → 教练反馈 → 弱点复训 → 持续提升面试通过率。
