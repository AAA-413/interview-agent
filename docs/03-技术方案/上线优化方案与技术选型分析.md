## 二、P0 级别优化（上线前必须完成）

### 2.1 RAG 知识库向量化升级

#### 当前方案
```python
# app/modules/knowledge_base/vector_service.py
def embed_text(self, text: str) -> list[float]:
    digest = hashlib.sha256(text.encode("utf-8")).digest()
    # 将哈希值转换为 16 维向量
    values = []
    for index in range(EMBEDDING_DIMENSIONS):
        start = index * 2
        segment = digest[start : start + 2]
        number = int.from_bytes(segment, byteorder="big", signed=False)
        values.append((number / 65535.0) * 2 - 1)
    return values
```

#### 当前方案的缺点
1. **无语义信息**：SHA-256 哈希是确定性的，相同文本得到相同向量，但语义相似的文本向量完全不同
2. **检索准确率极低**：实测只有 40% 左右，用户问答体验极差
3. **维度过低**：16 维无法表达复杂语义
4. **不可用于生产**：知识库功能基本废掉

#### 技术选型对比

| 方案 | 优点 | 缺点 | 成本 | 推荐度 |
|------|------|------|------|--------|
| **阿里云百炼 Embedding API** | 1. 与当前 LLM 同一平台<br>2. 无需部署<br>3. 中文效果好 | 1. 按 Token 计费<br>2. 依赖外部服务 | ¥0.0007/千tokens | ⭐⭐⭐⭐⭐ |
| **OpenAI text-embedding-3-small** | 1. 效果好（1536 维）<br>2. 成本低 | 1. 需要国际网络<br>2. 中文效果略逊 | $0.02/百万tokens | ⭐⭐⭐⭐ |
| **本地模型（bge-large-zh）** | 1. 无 API 调用成本<br>2. 数据不出本地 | 1. 需要 GPU 资源<br>2. 部署复杂 | 服务器成本 | ⭐⭐⭐ |
| **Sentence-Transformers** | 1. 开源免费<br>2. 模型丰富 | 1. CPU 推理慢<br>2. 需要自己部署 | 服务器成本 | ⭐⭐⭐ |

#### 推荐方案：阿里云百炼 Embedding API

**选择理由：**
1. 与当前 LLM 同一平台，API Key 复用，无需额外配置
2. 中文效果优秀（针对中文优化）
3. 无需部署，开箱即用
4. 成本可控（1000 个文档约 ¥1-2）

**实现方案：**

### 2.2 LLM 调用超时控制和异常处理

#### 当前方案
```python
# app/common/ai/llm_provider.py
self._providers["dashscope"] = ChatOpenAI(
    base_url=ai.base_url,
    api_key=ai.bailian_api_key,
    model=ai.model,
    temperature=ai.temperature,
    max_tokens=4096,
    request_timeout=180,  # 3 分钟超时
)
```

#### 当前方案的缺点
1. **超时时间过长**：180 秒对用户来说太久，容易流失
2. **无重试机制**：网络抖动导致失败后不重试
3. **无调用监控**：不知道哪些调用慢、哪些失败
4. **无降级策略**：LLM 故障时无备用方案

#### 技术选型对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **调整超时 + 重试** | 1. 简单直接<br>2. 无额外依赖 | 1. 无法解决 LLM 本身慢的问题 | ⭐⭐⭐⭐⭐ |
| **多 Provider 降级** | 1. 高可用<br>2. 成本优化 | 1. 需要多个 API Key<br>2. 逻辑复杂 | ⭐⭐⭐⭐ |
| **本地模型备份** | 1. 完全自主可控 | 1. 部署成本高<br>2. 效果可能差 | ⭐⭐⭐ |
| **缓存常见问题** | 1. 响应快<br>2. 省成本 | 1. 命中率低<br>2. 维护成本高 | ⭐⭐ |

#### 推荐方案：调整超时 + 重试 + 监控

**选择理由：**
1. 快速见效，工作量小
2. 覆盖 90% 的异常场景
3. 为后续多 Provider 降级打基础

**实现方案：**
```python
# app/common/ai/llm_provider.py
import time
from functools import wraps


class LlmProviderRegistry:
    def _init_default_providers(self) -> None:
        ai = settings.ai
        self._providers["dashscope"] = ChatOpenAI(
            base_url=ai.base_url,
            api_key=ai.bailian_api_key,
            model=ai.model,
            temperature=ai.temperature,
            max_tokens=4096,
            request_timeout=60,  # 改为 60 秒
            max_retries=2,  # 自动重试 2 次
        )

    def get_chat_model(self, provider: str | None = None) -> ChatOpenAI:
        key = provider or "dashscope"
        model = self._providers.get(key)
        if not model:
            raise ValueError(f"未找到 LLM Provider: {key}")

        # 包装调用，添加监控
        return self._wrap_with_monitoring(model, key)

    def _wrap_with_monitoring(self, model: ChatOpenAI, provider: str):
        original_ainvoke = model.ainvoke

        async def monitored_ainvoke(messages, **kwargs):
            start = time.time()
            try:
                result = await original_ainvoke(messages, **kwargs)
                duration = time.time() - start
                logger.info("LLM调用成功: provider=%s, model=%s, duration=%.2fs", provider, model.model_name, duration)
                return result
            except Exception as e:
                duration = time.time() - start
                logger.error(
                    "LLM调用失败: provider=%s, model=%s, duration=%.2fs, error=%s",
                    provider,
                    model.model_name,
                    duration,
                    str(e),
                )
                raise

        model.ainvoke = monitored_ainvoke
        return model
```

**工作量：** 1-2 小时  
**预期收益：** 
- 用户等待时间减少 50%
- 网络抖动导致的失败率降低 80%
- 可观测性提升，便于排查问题

### 3.1 评估服务并行化

#### 当前方案
```python
# app/modules/interview/evaluation_service.py
async def _evaluate_in_batches(self, ...):
    results = []
    for start in range(0, len(qa_records), self._batch_size):
        batch = qa_records[start : start + self._batch_size]
        report = await self._evaluate_batch(...)  # 串行执行
        results.append(report)
    return results
```

#### 当前方案的缺点
1. **串行执行**：10 题分 2 批，需要 20-30 秒
2. **用户等待久**：评估阶段体验差
3. **资源利用率低**：LLM API 支持并发，但未利用

#### 技术选型对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **asyncio.gather 并行** | 1. 简单直接<br>2. 速度提升 3-5x | 1. 并发过高可能触发限流 | ⭐⭐⭐⭐⭐ |
| **Celery 异步任务** | 1. 解耦<br>2. 可扩展 | 1. 架构复杂<br>2. 当前无必要 | ⭐⭐⭐ |
| **流式评估** | 1. 用户体验好 | 1. 实现复杂<br>2. 前端改动大 | ⭐⭐⭐ |

#### 推荐方案：asyncio.gather 并行 + 限流控制

**选择理由：**
1. 改动最小，只需修改一处代码
2. 速度提升明显（3-5x）
3. 可配置并发数，避免触发 API 限流

**实现方案：**
```python
# app/modules/interview/evaluation_service.py
import asyncio
from asyncio import Semaphore

class UnifiedEvaluationService:
    def __init__(self):
        # ...
        self._max_concurrent_batches = 3  # 最多 3 个批次并行
    
    async def _evaluate_in_batches(self, ...):
        semaphore = Semaphore(self._max_concurrent_batches)
        
        async def evaluate_with_limit(batch):
            async with semaphore:
                return await self._evaluate_batch(chat_model, session_id, 
                                                   resume_context, reference_context, batch)
        
        # 创建所有批次任务
        tasks = []
        for start in range(0, len(qa_records), self._batch_size):
            batch = qa_records[start : start + self._batch_size]
            tasks.append(evaluate_with_limit(batch))
        
        # 并行执行
        results = await asyncio.gather(*tasks, return_exceptions=True)
        
        # 处理异常
        valid_results = []
        for i, result in enumerate(results):
            if isinstance(result, Exception):
                logger.error("批次%d评估失败: %s", i, result)
                valid_results.append(None)
            else:
                valid_results.append(result)
        
        return valid_results
```

**工作量：** 2-3 小时  
**预期收益：** 评估速度 30s → 10s

### 4.2 向量数据库升级（pgvector）

#### 当前方案
```python
# 全表扫描，O(n) 复杂度
for chunk in all_chunks:
    similarity = cosine_similarity(query_vector, chunk.embedding)
```

#### 当前方案的缺点
1. **检索性能差**：全表扫描 O(n)，无法支持大规模知识库
2. **无向量索引**：每次查询都要计算所有向量的相似度
3. **扩展性差**：文档数量 > 1000 后性能急剧下降

#### 技术选型对比（参考 Ragent 方案）

| 方案 | 优点 | 缺点 | 推荐场景 | 推荐度 |
|------|------|------|---------|--------|
| **pgvector** | 1. 无需额外服务<br>2. 与 PostgreSQL 集成<br>3. 支持 HNSW 索引 | 1. 性能略低于专用库 | 中小规模（<100万向量） | ⭐⭐⭐⭐⭐ |
| **Qdrant** | 1. 性能优秀<br>2. 功能丰富<br>3. 易于部署 | 1. 需独立部署<br>2. 额外维护成本 | 大规模（>100万向量） | ⭐⭐⭐⭐ |
| **Milvus** | 1. 企业级<br>2. 生态完善<br>3. 超高性能 | 1. 部署复杂<br>2. 资源消耗大 | 超大规模（>1000万向量） | ⭐⭐⭐ |

#### 推荐方案：pgvector（当前阶段）

**选择理由：**
1. 无需额外服务，与现有 PostgreSQL 集成
2. 支持 HNSW 索引，性能提升 100x
3. 部署简单，维护成本低
4. 支持 100 万级向量，满足当前需求

**实现方案：**

```sql
-- 1. 安装 pgvector 扩展
CREATE EXTENSION vector;

-- 2. 修改表结构
ALTER TABLE knowledge_chunks
ADD COLUMN embedding vector(768);  -- 768 维向量（根据 Embedding 模型调整）

-- 3. 创建 HNSW 索引
CREATE INDEX ON knowledge_chunks
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

-- 4. 向量检索查询
SELECT id, content, title, 1 - (embedding <=> :query_vector) AS similarity
FROM knowledge_chunks
WHERE kb_id = :kb_id
ORDER BY embedding <=> :query_vector
LIMIT :top_k;
```

```python
from sentence_transformers import CrossEncoder


class RerankService:
    def __init__(self, model_name: str = "BAAI/bge-reranker-large"):
        self.model = CrossEncoder(model_name)

    async def rerank(self, query: str, chunks: List[RagReferenceDTO], top_k: int) -> List[RagReferenceDTO]:
        """使用 Cross-Encoder 模型重排序"""

        # 1. 构造查询-文档对
        pairs = [(query, chunk.content_preview) for chunk in chunks]

        # 2. 计算相关性分数（在线程池中执行，避免阻塞）
        loop = asyncio.get_event_loop()
        scores = await loop.run_in_executor(None, self.model.predict, pairs)

        # 3. 按分数排序
        scored_chunks = list(zip(chunks, scores))
        scored_chunks.sort(key=lambda x: x[1], reverse=True)

        # 4. 更新分数并返回 Top-K
        reranked = []
        for chunk, score in scored_chunks[:top_k]:
            chunk.score = round(float(score), 4)
            reranked.append(chunk)

        return reranked
```

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import List


@dataclass
class SearchChannelResult:
    channel_name: str
    chunks: List[RagReferenceDTO]
    confidence: float
    latency_ms: int


class SearchChannel(ABC):
    @abstractmethod
    def get_name(self) -> str:
        pass

    @abstractmethod
    def get_priority(self) -> int:
        pass

    @abstractmethod
    def is_enabled(self, context: SearchContext) -> bool:
        pass

    @abstractmethod
    async def search(self, context: SearchContext) -> SearchChannelResult:
        pass


class IntentDirectedSearchChannel(SearchChannel):
    """意图定向检索：基于意图识别结果定向检索"""

    def get_priority(self) -> int:
        return 1  # 最高优先级

    async def search(self, context: SearchContext) -> SearchChannelResult:
        # 1. 提取 KB 意图
        kb_intents = [i for i in context.intents if i.type == "KB"]

        # 2. 并行检索所有意图对应的知识库
        tasks = [self._retrieve_by_kb(context.question, intent.kb_id, context.top_k) for intent in kb_intents]
        results = await asyncio.gather(*tasks)

        # 3. 合并结果
        all_chunks = [chunk for result in results for chunk in result]
        return SearchChannelResult(
            channel_name="IntentDirected",
            chunks=all_chunks,
            confidence=max(i.score for i in kb_intents),
            latency_ms=...,
        )


# 多路检索引擎
class MultiChannelRetrievalEngine:
    def __init__(self, channels: List[SearchChannel]):
        self.channels = sorted(channels, key=lambda c: c.get_priority())

    async def retrieve(self, context: SearchContext) -> List[RagReferenceDTO]:
        # 1. 并行执行所有启用的通道
        enabled_channels = [c for c in self.channels if c.is_enabled(context)]
        results = await asyncio.gather(*[c.search(context) for c in enabled_channels])

        # 2. 合并所有通道的结果
        all_chunks = []
        for result in results:
            all_chunks.extend(result.chunks)

        # 3. 后处理：去重 → 重排序 → Top-K
        chunks = self._deduplicate(all_chunks)
        chunks = await self._rerank(context.question, chunks, context.top_k)
        return chunks[: context.top_k]
```

- 探测成功 → 恢复正常

#### Python 实现建议

```python
from enum import Enum
from dataclasses import dataclass
import time


class CircuitState(Enum):
    CLOSED = "closed"  # 正常
    OPEN = "open"  # 熔断
    HALF_OPEN = "half_open"  # 半开


@dataclass
class ModelCandidate:
    provider: str
    model: str
    priority: int
    api_key: str
    base_url: str


class CircuitBreaker:
    def __init__(self, failure_threshold: int = 5, timeout: int = 60):
        self.state = CircuitState.CLOSED
        self.failure_count = 0
        self.failure_threshold = failure_threshold
        self.timeout = timeout
        self.last_failure_time = None

    def record_success(self):
        self.failure_count = 0
        self.state = CircuitState.CLOSED

    def record_failure(self):
        self.failure_count += 1
        if self.failure_count >= self.failure_threshold:
            self.state = CircuitState.OPEN
            self.last_failure_time = time.time()

    def can_attempt(self) -> bool:
        if self.state == CircuitState.CLOSED:
            return True
        if self.state == CircuitState.OPEN:
            if time.time() - self.last_failure_time > self.timeout:
                self.state = CircuitState.HALF_OPEN
                return True
            return False
        return True  # HALF_OPEN


class ModelRoutingService:
    def __init__(self, candidates: List[ModelCandidate]):
        self.candidates = sorted(candidates, key=lambda c: c.priority)
        self.breakers = {c.provider: CircuitBreaker() for c in candidates}

    async def chat_completion(self, messages: List[dict], stream: bool = False) -> AsyncIterator[str]:
        """带容错的模型调用"""

        for candidate in self.candidates:
            breaker = self.breakers[candidate.provider]

            if not breaker.can_attempt():
                continue

            try:
                # 尝试调用模型
                async for chunk in self._call_model(candidate, messages, stream):
                    yield chunk

                breaker.record_success()
                return

            except Exception as e:
                breaker.record_failure()
                logger.warning(f"模型 {candidate.provider} 调用失败: {e}")
                continue

        raise Exception("所有候选模型均不可用")
```

```python
from rank_bm25 import BM25Okapi
import jieba


class BM25SearchChannel(SearchChannel):
    def __init__(self, chunk_repository):
        self.chunk_repository = chunk_repository
        self.bm25_index = {}  # kb_id -> BM25Okapi

    async def search(self, context: SearchContext) -> SearchChannelResult:
        # 1. 分词
        query_tokens = jieba.lcut(context.question)

        # 2. BM25 检索
        bm25 = self.bm25_index.get(context.kb_id)
        scores = bm25.get_scores(query_tokens)

        # 3. 返回 Top-K
        top_indices = np.argsort(scores)[-context.top_k :][::-1]
        chunks = [self.chunks[i] for i in top_indices]

        return SearchChannelResult(channel_name="BM25Keyword", chunks=chunks, confidence=max(scores), latency_ms=...)


# 融合策略
class HybridFusionStrategy:
    def fuse(
        self, vector_results: List[RagReferenceDTO], bm25_results: List[RagReferenceDTO], alpha: float = 0.7
    ) -> List[RagReferenceDTO]:
        """加权融合：alpha * vector + (1-alpha) * bm25"""

        score_map = {}
        for chunk in vector_results:
            score_map[chunk.id] = alpha * chunk.score

        for chunk in bm25_results:
            if chunk.id in score_map:
                score_map[chunk.id] += (1 - alpha) * chunk.score
            else:
                score_map[chunk.id] = (1 - alpha) * chunk.score

        # 按融合分数排序
        sorted_chunks = sorted(score_map.items(), key=lambda x: x[1], reverse=True)
        return [chunk_id for chunk_id, score in sorted_chunks]
```

### 10.7 核心要点总结

1. **向量化是基础**：SHA-256 哈希必须替换为真实 Embedding 模型
2. **向量库是关键**：pgvector 或 Qdrant 提供高性能检索
3. **多路检索是进阶**：意图定向 + 全局向量提升召回率
4. **重排序是精髓**：Cross-Encoder 二次精排提升准确率
5. **容错是保障**：多模型路由 + 熔断器保证高可用
