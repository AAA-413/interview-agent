# 语音识别方案选型

> 文档日期：2026-05-21
> 当前状态：已落地 voice-lite 第一版

---

## 一、结论

当前语音输入采用 **录音上传 + 后端本地 faster-whisper 转写**。

不再使用浏览器自带 `SpeechRecognition` 做正式识别。浏览器识别接入快，但中文长句、技术词、网络状态和浏览器版本都会影响效果，无法满足面试回答训练的稳定性要求。

当前方案不是全量实时语音面试，而是 voice-lite：

```text
用户点击语音输入
  ↓
前端 MediaRecorder 录音
  ↓
停止录音后上传音频
  ↓
FastAPI 调用本地 faster-whisper 转写
  ↓
转写文本填入回答框
  ↓
用户可编辑后提交
  ↓
继续走 DeepSeek 追问和评分链路
```

---

## 二、选型目标

第一阶段目标不是“像真人一样实时对话”，而是让校招/转岗同学可以用口头表达完成答题训练。

优先级如下：

1. 中文识别质量优先于实时性。
2. 不影响现有 DeepSeek 出题、追问、评分链路。
3. 不新增第三方语音 API key 依赖。
4. 本地开发可直接跑，隐私风险低。
5. 后续可以替换为云端 STT 或实时 STT。

---

## 三、方案对比

| 方案 | 优点 | 问题 | 结论 |
|------|------|------|------|
| 浏览器 `SpeechRecognition` | 接入最快，无后端改造 | 中文技术词差、稳定性差、浏览器兼容不一致 | 放弃作为正式方案 |
| 前端 `MediaRecorder` + 本地 faster-whisper | 中文质量更稳、无额外 API key、隐私较好 | 首次下载模型慢，CPU 转写有几秒延迟 | 当前采用 |
| DashScope / 讯飞 / 火山等云端 STT | 中文效果和实时能力更强，可做热词 | 需要账号、费用、网络和隐私评估 | 生产增强候选 |
| WebSocket/WebRTC 实时语音 | 体验最接近真人面试 | 状态机、打断、静音检测、延迟控制复杂 | 后续阶段 |

## 四、当前实现

### 前端

文件：

- `frontend/src/pages/InterviewPage.tsx`
- `frontend/src/api/interview.ts`
- `frontend/src/types/interview.ts`

能力：

- 使用 `MediaRecorder` 采集麦克风音频。
- 支持录音中、转写中、失败提示等状态。
- 停止录音后上传音频到后端。
- 后端返回文本后追加到回答框。
- 提交回答仍走原有 `submitAnswer`。

### 后端

文件：

- `app/modules/interview/voice_service.py`
- `app/modules/interview/router.py`
- `app/modules/interview/schemas.py`
- `app/config.py`

接口：

```text
POST /api/interview/voice/transcribe
```

请求：

- `multipart/form-data`
- 字段名：`file`
- 支持常见浏览器录音格式，如 `webm` / `ogg` / `m4a` / `wav`

返回：

```json
{
  "text": "转写后的回答文本",
  "language": "zh",
  "duration": 4.75
}
```

## 五、运行边界

当前语音识别 **不在 Docker 容器里**。

本地开发环境的边界是：

| 组件 | 运行位置 |
|------|----------|
| PostgreSQL | Docker |
| Redis | Docker |
| MinIO | Docker |
| FastAPI 后端 | 本机 `.venv` |
| faster-whisper STT | 本机 `.venv` 内，由 FastAPI 调用 |
| Whisper 模型文件 | 本机 Hugging Face cache |
| React 前端 | 本机 Vite |

模型首次调用时会下载到本机缓存目录，通常是：

```bash
~/.cache/huggingface/hub
```

为了降低国内网络下载失败概率，当前默认配置了 Hugging Face 镜像端点：

```text
APP_VOICE_INTERVIEW_STT_HF_ENDPOINT=https://hf-mirror.com
```

## 六、配置项

配置类：`VoiceInterviewSettings`

环境变量前缀：`APP_VOICE_INTERVIEW_`

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `STT_PROVIDER` | `local_whisper` | 当前仅支持本地 Whisper |
| `STT_MODEL` | `small` | 模型大小，质量和速度折中 |
| `STT_DEVICE` | `cpu` | 当前按本机 CPU 跑 |
| `STT_COMPUTE_TYPE` | `int8` | 降低 CPU 推理成本 |
| `STT_HF_ENDPOINT` | `https://hf-mirror.com` | 模型下载镜像 |
| `MAX_AUDIO_SIZE_MB` | `25` | 单段录音上传上限 |

可在 `.env` 中覆盖：

```bash
APP_VOICE_INTERVIEW_STT_MODEL=small
APP_VOICE_INTERVIEW_STT_DEVICE=cpu
APP_VOICE_INTERVIEW_STT_COMPUTE_TYPE=int8
APP_VOICE_INTERVIEW_STT_HF_ENDPOINT=https://hf-mirror.com
APP_VOICE_INTERVIEW_MAX_AUDIO_SIZE_MB=25
```

## 七、验证方式

### 质量检查

```bash
./scripts/quality_check.sh
```

### 本地接口冒烟

macOS 可用 `say` 生成一段测试音频：

```bash
say -v Tingting -o /tmp/interview-voice-test.aiff '你好，这是语音识别测试。我正在模拟面试回答。'
```

登录后调用：

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:8002/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"<username>","password":"<password>"}' | jq -r '.access_token')

curl -s -X POST http://127.0.0.1:8002/api/interview/voice/transcribe \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@/tmp/interview-voice-test.aiff;type=audio/aiff"
```

预期返回包含：

```json
{
  "text": "你好,这是语音识别测试,我正在模拟面试回答。"
}
```

## 八、已知限制

- 首次使用会下载模型，冷启动较慢。
- CPU 转写不是实时字幕，停止录音后需要等待数秒。
- 对非常长的回答，建议按题分段录音。
- 当前没有做热词增强，技术词如框架名、英文缩写仍可能需要用户手动修正。
- 当前没有语音播题、打断和全双工实时对话。

## 九、后续升级方向

1. 增加云端 STT Provider 接口，支持 DashScope / 讯飞 / 火山等服务按配置切换。
2. 增加面试技术词热词表，如 `Redis`、`RAG`、`MCP`、`Spring Boot`。
3. 增加转写结果编辑区和“一键替换/追加”交互。
4. 增加表达质量指标：停顿、口头禅、过短回答、重复表达。
5. 进入后续阶段时再做实时语音面试，包括 VAD、WebSocket、TTS、打断和状态机。
