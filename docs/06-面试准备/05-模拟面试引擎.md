# 模拟面试引擎 — 面试技术细节

## 一、整体流程

```
用户选择面试方向（skills/python-backend）+ 难度 + 上传简历（可选）
  ↓
并行出题（asyncio.gather，2次LLM调用并行）
  ├─ 简历题: 基于简历内容出题（占60%）
  └─ 方向题: 基于技能方向出题（占40%）
  ↓
用户逐题作答
  ↓
追问决策（1次LLM调用，最多追问2次）
  ├─ shouldFollowUp=true → 生成追问问题
  └─ shouldFollowUp=false → 进入下一题
  ↓
异步评估（Redis Stream，全部作答后触发）
  ├─ 知识题: 对比参考答案+关键点评估
  └─ 项目题: 四维度评估（真实性/技术深度/深度/表达）
  ↓
生成面试报告 + PDF导出
```

**出题比例**: `RESUME_QUESTION_RATIO = 0.6`（有简历时60%简历题+40%方向题）

**降级策略**:
- 简历题失败 → 全部出方向题
- 方向题失败 → 使用简历题
- 全部失败 → 回退到默认问题（预设的通用面试题）

**结构化输出**: 通过 `StructuredOutputInvoker` 让 LLM 返回 `_QuestionListDTO`，包含：

## 八、面试常见追问

**Q: 为什么用并行出题而不是串行？**
A: 简历题和方向题是独立的 LLM 调用，没有数据依赖。`asyncio.gather` 并行执行可以将出题时间从串行的 2 次 LLM 调用（约 6-10 秒）缩短为 1 次的时间（约 3-5 秒）。

**Q: 追问机制的 LLM 调用次数？**
A: 每道题回答后 1 次 LLM 调用判断是否追问。如果追问，再 1 次调用生成追问问题。最多 2 次追问，所以每道题最多 3 次 LLM 调用（决策1 + 追问生成1 + 追问决策1）。

**Q: 知识题和项目题为什么要分开评估？**
A: 评估维度不同。知识题有标准答案和关键点，评估重点是"答对了多少"；项目题没有标准答案，评估重点是"是否真实参与、技术深度如何、表达是否清晰"，需要四维度打分。混在一起评估会导致 LLM 评估标准混乱。

**Q: 并发评估怎么控制？**
A: 用 `asyncio.Semaphore(3)` 限制最多 3 个并发 LLM 调用，避免同时发起太多请求导致 API 限流或内存占用过高。
