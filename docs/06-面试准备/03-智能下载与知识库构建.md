# 智能下载与知识库自动构建 — 面试技术细节

## 一、整体架构（两阶段设计）

```
阶段1: 计划生成（用户确认）
  用户描述需求 → PlanningAgent.plan_download() → 结构化下载计划 → 前端展示

阶段2: 计划执行（后台任务）
  用户确认计划 → BackgroundTasks 后台执行
    ├─ DownloadExecutionAgent: 网页抓取 + 搜索 + 博客
    ├─ GitHubExecutionAgent: GitHub仓库搜索 + 文档抓取
    ├─ 动态任务扩展（搜索结果自动生成子任务）
    ├─ QualityAgent: 质量检查（失败重试最多3次）
    ├─ SummaryAgent: 文档精炼（结构化目录+要点提炼）
    └─ 自动入库 + 触发向量索引
```

## 二、阶段1: 计划生成

**代码位置**: `smart_download_router.py:138-210` + `planning_agent.py:386-688`

**PlanningAgent.plan_download() 流程**:
1. **意图分析**（1次LLM调用）: 提取 topic、resource_types、keywords、target_resources
2. **任务生成**（1次LLM调用）: 根据意图生成具体下载任务列表

**任务类型**:

- `fetch_url`: 直接抓取指定URL
- `search_web`: 搜索引擎搜索后抓取结果
- `fetch_blog`: 抓取博客文章
- `search_github`: GitHub仓库搜索（标记为动态任务）
- `fetch_github_repo`: 抓取仓库文档
- `fetch_github_file`: 抓取单个文件

**计划存储**: Redis JSON，TTL 1小时，key 格式 `smart_download:{user_id}:plan:{plan_id}`

```python
for step in plan["steps"]:
```

```
原始HTML → LLM清洗 → 结构化Markdown（移除无关内容，保留代码块，控制1500字以内）
```

### 3.3 内容整合（分层合成策略）

**代码位置**: `execution_agent.py:609-852`（DownloadExecutionAgent.integrate_contents）

**策略**（`execution_agent.py:705`）:
- **≤3个来源**: 直接拼接所有内容，1次LLM调用整合为3000字文档
- **>3个来源**: 分组摘要（每组最多3个）→ 合并整合

  - 最后1次LLM调用合并所有组摘要为3000字文档

**代码位置**: `summary_agent.py:210-255`（SummaryAgent.refine_document）

1次LLM调用，生成结构化目录 + 核心要点提炼，保留技术细节和代码示例。

### 3.5 质量检查与选择性重试

**代码位置**: `app/modules/agent_orchestration/agents/quality_agent.py`

**两阶段评估架构**:

```
执行结果 → Phase A（逐任务规则评估，0次LLM）
  ├─ substance: 长度 + 模板检测 + 句子密度
  ├─ relevance: 关键词匹配（宽松模式）
  └─ 返回 failed_task_indices
       ↓
  通过率 <50% → 直接失败
  全部通过 → 跳过 Phase B
  部分失败 → Phase B（整体LLM评估，1次调用）
       ├─ coverage: 覆盖度
       ├─ diversity: 多样性
       └─ expanded_keywords: 扩展关键词（供重试使用）
```

**选择性重试**:
```python
# successful_results: 跨重试轮次保留成功结果
for retry in range(max_retries):
    if retry == 0:
        steps_to_execute = all_steps  # 第一轮：全部执行
    else:
        steps_to_execute = failed_task_indices  # 重试轮：只执行失败任务

    # 合并新旧结果后重新质检
    successful_results.update(new_results)
    execution_results = [successful_results.get(i, {}) for i in range(max_idx + 1)]
    quality_result = await quality_agent.check(..., expanded_keywords=expanded_keywords)

    if quality_result["passed"]:
        break
    # expanded_keywords 供下一轮 Phase A 使用
    expanded_keywords = quality_result.get("expanded_keywords", [])
```

## 六、LLM 调用次数分析

一次完整智能下载（假设5个步骤，3个来源）:
- 计划阶段: 意图分析(1) + 任务生成(1) = **2次**
- 执行阶段: 5个下载 × 内容清洗(1) = **5次**
- 整合阶段: 内容整合(1) + 标题摘要(1) = **2次**
- 精炼阶段: 文档精炼(1) = **1次**
- 质检阶段: 质量检查(1) = **1次**

## 七、面试常见追问

**Q: 为什么不直接让用户手动上传文档到知识库？**
A: 智能下载的核心价值是"用户只需描述需求，系统自动搜索、清洗、整合、入库"。手动上传需要用户自己找资料、下载、格式化，智能下载把这些步骤全自动化了。

**Q: 内容清洗的必要性？**
A: 网页原始HTML包含大量噪声（导航栏、广告、页脚、侧边栏），直接入库会降低检索质量。LLM清洗后保留核心知识和代码示例，用结构化Markdown格式存储，显著提升后续RAG问答的质量。

**Q: 分层合成策略的设计动机？**
A: 当来源超过3个时，所有内容拼接后可能超过 LLM 上下文窗口限制，且信息密度下降。分组摘要先压缩每组信息，再合并整合，既避免了 token 超限，又保证了信息的全面性。

**Q: 质量检查检查什么？**
A: 两阶段评估。Phase A 用规则逐任务检查：内容实质性（长度够不够、是不是模板页面）和主题相关性（关键词命中率，宽松模式避免误杀）。Phase B 用 LLM 整体评估：发送元数据摘要+800字预览，检查覆盖度和多样性。Phase A 管"单任务合格"，Phase B 管"整体搭配合理"。

**Q: 选择性重试和原来有什么区别？**
A: 原来10个任务中1个失败 → 清空全部结果重新下载10个。现在 Phase A 返回 `failed_task_indices`（如 [3, 5]），只重试 task_3 和 task_5，保留其余8个成功结果。用 `successful_results` 字典跨轮次持久化，合并后重新质检。下载成本从 O(n) 降到 O(失败数)。

**Q: 宽松模式的 relevance 评分是怎么设计的？**
A: 三层兜底：1）无法提取关键词（如纯停用词）→ 60分默认通过；2）有关键词但0命中 → 25分（低于阈值30，标记失败但不判死）；3）有命中 → max(30, 正常计算)。同时 Phase B 输出 `expanded_keywords`（同义词/相关词），重试时合并到关键词列表，原来0命中的内容可能因为扩展词命中而通过。
