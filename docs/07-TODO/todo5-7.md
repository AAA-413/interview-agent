 问题分析：知识库自动索引失败（状态卡在"待索引"）

  状态：✅ 已修复（2026-05-07）
  修复文件：knowledge_base/upload_service.py, resume/upload_service.py
  修复方式：在 _enqueue_index/_enqueue_analysis 前增加 await db.commit()                                                                                                                                                                                                                                
                                                                                                                                                                                                                                                                                  
  根本原因：事务提交前分发任务的竞争条件                                                                                                                                                                                                                                          
                                                                                                                                                                                                                                                                                  
  知识库文件上传路径存在一个竞争条件 Bug。                                                                                                                                                                                                                                        
                                                                                                                                                                                                                                                                                  
  在 upload_service.py:67：                                                                                                                                                                                                                                                       
  entity = await knowledge_base_persistence_service.save(db, entity)  # 仅 flush，未 commit                                                                                                                                                                                       
                                                                                                                                                                                                                                                                                  
  if source_text:                                                                                                                                                                                                                                                                 
      await self._enqueue_index(entity.id)  # ← 在 commit 之前就发到了 Redis Stream！                                                                                                                                                                                             
                                                                                                                                                                                                                                                                                  
  流程是：                                                                                                                                                                                                                                                                        
  1. save() 调用 db.add(entity) + db.flush() — 实体获得 ID，但仍在当前事务中，未提交                                                                                                                                                                                              
  2. _enqueue_index(entity.id) 发送消息到 Redis Stream                                                                                                                                                                                                                            
  3. Worker 收到消息，用新数据库会话执行 find_by_id_or_throw() → 找不到（还未 commit）→ 抛异常                                                                                                                                                                                    
  4. Handler 的 except 块尝试把状态设为 FAILED → 但 update_index_status() 里 find_by_id() 返回 None（依然没提交） → 静默退出，状态保持 PENDING 不动                                                                                                                               
                                                                                                                                                                                                                                                                                  

  为什么从 5 月 6 号到现在一直是"待索引"                                                                                                                                                                                                                                          
                                                                                                                                                                                                                                                                                  
  这就是表现：消息被发出去了，Worker 也收到了，但处理的时候实体还没落到数据库里。Worker 既不能完成索引，也无法把状态更新为 FAILED（因为都查不到该记录）。状态就永远卡在 PENDING。                                                                                                 
                                                                                                                                                                                                                                                                                  
  对比：URL 抓取路径是正确的                                                                                                                                                                                                                                                      
                  
  fetch_service.py:71-76 顺序就是对的：                                                                                                                                                                                                                                           
  entity = await knowledge_base_persistence_service.save(db, entity)
  await db.commit()                         # 先提交事务                                                                                                                                                                                                                          
  await knowledge_base_upload_service._enqueue_index(entity.id)  # 再分发任务                                                                                                                                                                                                     
                                                                                                                                                                                                                                                                                  
  文件上传路径缺少了 await db.commit()，且 router.py 里也没有像简历上传那样在 commit 之后才分发的逻辑。这实际上和之前修复的简历竞争条件 bug（commit 532f212）是同一个问题，只是知识库这里忘了改。                                                                                 
                                                                                                                                                                                                                                                                                  
  修复方案                                                                                                                                                                                                                                                                        
                                                                                                                                                                                                                                                                                  
  需要将 upload_service.py 中的入队操作移到 router.py 中，在 db.commit() 之后执行。原理和 resume/router.py 已修复的模式一样。
