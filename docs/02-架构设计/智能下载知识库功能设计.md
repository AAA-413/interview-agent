# 智能下载知识库功能设计

## 版本信息
- 版本：v1.1
- 创建时间：2024-01
- 最后更新：2026-05-07

## 功能概述

智能下载知识库功能允许用户通过自然语言描述需求，由AI自动分析并生成下载计划，用户确认后执行下载，将网络资源自动抓取并导入知识库。

### 核心价值
- **智能理解**：用户只需描述需求，AI自动识别意图和目标资源
- **计划确认**：生成详细计划供用户审核，避免误操作
- **质量保证**：4步Agent编排（Planning→Execution→Quality→Summary），自动质检和重试
- **进度可视**：实时显示下载进度和状态

## 架构设计

### 两阶段流程

```
阶段1：生成计划（Planning）
用户输入 → PlanningAgent分析 → 生成下载计划 → 返回给用户确认

阶段2：执行下载（Execution + Quality + Summary）
用户确认 → 后台任务执行 → 实时进度更新 → 完成通知
```

### Agent编排系统

采用5步编排模式（AgentOrchestrator）：

```
0. SmartDecisionTree（决策）
   - LLM驱动的路径选择
   - 输出置信度和预估成本

1. PlanningAgent（规划）
   - 分析用户意图
   - 识别目标资源类型（官方文档、博客、GitHub、论文等）
   - 生成下载步骤列表
   - 估算时间和大小

2. ExecutionAgent（执行）
   - 根据计划逐步执行下载
   - 支持多种下载方式：
     * fetch_url：直接抓取URL
     * search_web：搜索引擎查找
     * fetch_blog：博客平台抓取（CSDN、掘金、知乎、Medium等）
     * search_github / fetch_github_repo：GitHub仓库搜索和抓取
   - 调用MCP服务进行内容抓取
   - 支持动态任务扩展（如GitHub搜索结果自动生成抓取任务）
   - 统一返回 AgentMessage 协议

3. QualityAgent（质检）
   - 四维度评分：
     * 完整性（Completeness）：是否下载了所有计划的资源
     * 准确性（Accuracy）：内容是否符合用户需求
     * 质量（Quality）：内容质量是否达标
     * 可用性（Usability）：是否可以正常使用
   - 质量阈值：0.7（低于此值触发重试）
   - 最多重试3次

4. SummaryAgent（总结）
   - 生成执行报告
   - 统计下载结果
   - 文档精炼（结构化目录+要点提炼）
   - 提供优化建议
```

### 内容整合策略（S-P3 分层合成）

当下载来源超过 3 个时，采用分层合成策略避免 LLM 上下文溢出：

```
来源1-3 → LLM摘要 → 摘要A
来源4-6 → LLM摘要 → 摘要B
来源7+  → LLM摘要 → 摘要C
         ↓
摘要A+B+C → LLM最终整合 → 完整文档
```

**实现位置**：`ExecutionAgent.integrate_contents()`
- ≤3 个来源：直接合并到一个 prompt 整合
- >3 个来源：每 3 个一组生成 ~500 字摘要，再合并所有摘要生成最终文档

### AgentMessage 协议（A-P1）

所有 ExecutionAgent 子类返回统一的 `AgentMessage` Pydantic 模型：

```python
class AgentMessage(BaseModel):
    task_id: str
    agent_type: str
    status: str  # "success" | "failed"
    result: Optional[Dict[str, Any]] = None
    error: Optional[str] = None
    metadata: Dict[str, Any] = Field(default_factory=dict)
```

**注意**：Router 层需要通过 `model_dump()` 将 AgentMessage 转为 dict 后再传递给下游 Agent。

### 技术栈

**后端：**
- FastAPI：API路由和异步处理
- AgentOrchestrator：Agent编排器
- MCP Service：内容抓取服务
- PostgreSQL + pgvector：知识库存储
- Redis：计划缓存 + 任务进度 + 取消标志
- 智谱 Embedding-3：文本向量化（2048维截断到1536维匹配pgvector）

**前端：**
- React + TypeScript
- Ant Design / Tailwind CSS
- 实时进度轮询（每2秒）

## 数据模型

### 请求模型

```python
class PlanDownloadRequest(BaseModel):
    """生成下载计划请求"""

    user_input: str  # 用户需求描述
    max_downloads: int = 10  # 最大下载数量（1-20）
    kb_id: Optional[int] = None  # 目标知识库ID（可选）


class ExecuteDownloadRequest(BaseModel):
    """执行下载请求"""

    plan_id: str  # 计划ID
    kb_id: Optional[int] = None  # 目标知识库ID
    kb_name: Optional[str] = None  # 知识库名称（创建新库时）
    kb_description: Optional[str] = None  # 知识库描述
```

### 响应模型

```python
class DownloadPlan(BaseModel):
    """下载计划"""

    plan_id: str  # 计划ID
    user_input: str  # 用户输入
    intent: Dict[str, Any]  # 意图分析结果
    steps: List[DownloadStep]  # 下载步骤列表
    estimated_time: str  # 估算时间
    estimated_size: str  # 估算大小
    total_steps: int  # 总步骤数


class DownloadStep(BaseModel):
    """下载步骤"""

    step_id: int  # 步骤ID
    action: str  # 动作类型（fetch_url/search_web/fetch_blog）
    params: Dict[str, Any]  # 参数
    description: str  # 描述
    source_type: str  # 资源类型（official/blog/github/arxiv/general）


class DownloadProgress(BaseModel):
    """下载进度"""

    task_id: str  # 任务ID
    status: str  # 状态（planning/executing/quality_check/completed/failed/cancelled）
    current_step: int  # 当前步骤
    total_steps: int  # 总步骤数
    progress_percent: int  # 进度百分比
    message: str  # 状态消息
    retry_count: int  # 重试次数
    downloaded_files: List[Dict[str, Any]]  # 已下载文件列表
    quality_score: Optional[float] = None  # 质量分数
```

## API接口

### 1. 生成下载计划

```
POST /api/agent/smart-download/plan

Request:
{
  "user_input": "下载 FastAPI 官方文档和教程",
  "max_downloads": 10,
  "kb_id": 1
}

Response:
{
  "plan_id": "uuid-xxx",
  "user_input": "下载 FastAPI 官方文档和教程",
  "intent": {
    "topic": "FastAPI",
    "resource_types": ["official_docs", "tutorials"]
  },
  "steps": [
    {
      "step_id": 1,
      "action": "fetch_url",
      "params": {"url": "https://fastapi.tiangolo.com/"},
      "description": "抓取 FastAPI 官方文档首页",
      "source_type": "official"
    }
  ],
  "estimated_time": "300秒",
  "estimated_size": "5000KB",
  "total_steps": 10
}
```

### 2. 执行下载计划

```
POST /api/agent/smart-download/execute

Request:
{
  "plan_id": "uuid-xxx",
  "kb_id": 1
}

Response:
{
  "task_id": "task-xxx",
  "message": "下载任务已启动",
  "plan_id": "uuid-xxx"
}
```

### 3. 查询下载进度

```
GET /api/agent/smart-download/progress/{task_id}

Response:
{
  "task_id": "task-xxx",
  "status": "executing",
  "current_step": 3,
  "total_steps": 10,
  "progress_percent": 30,
  "message": "正在下载第3个资源...",
  "retry_count": 0,
  "downloaded_files": [
    {
      "step_id": 1,
      "description": "FastAPI 官方文档首页",
      "size": 500
    }
  ],
  "quality_score": null
}
```

### 4. 取消下载任务（C-P4）

```
POST /api/agent/smart-download/cancel/{task_id}

Response:
{
  "message": "取消请求已提交",
  "task_id": "task-xxx"
}
```

**实现机制**：
- 通过 Redis flag 标记取消请求（24h 过期）
- 执行循环在以下检查点检查取消标志：
  1. 每个下载步骤开始前
  2. 扩展任务执行前
  3. 质量检查前
- 取消后进度状态设为 `"cancelled"`，前端停止轮询

## MCP服务集成

### 支持的资源类型

1. **官方文档**：直接URL抓取
2. **博客平台**：
   - CSDN：`https://blog.csdn.net/`
   - 掘金：`https://juejin.cn/`
   - 知乎：`https://zhuanlan.zhihu.com/`
   - Medium：`https://medium.com/`
   - 简书：`https://www.jianshu.com/`
3. **GitHub**：仓库README和文档
4. **学术论文**：arXiv等
5. **通用网页**：任意URL

### 抓取流程

```python
# 1. 发送抓取请求
result = await mcp_service.fetch_document(url)

# 2. 解析内容
content = result["content"]  # Markdown格式
metadata = result["metadata"]  # 标题、作者等

# 3. 保存到知识库
await knowledge_service.add_document(kb_id=kb_id, content=content, metadata=metadata)
```

## 成本控制

### 预算管理

```python
# 设置预算
cost_controller.set_budget(max_cost=1.0)  # 最多1元

# 检查预算
if not cost_controller.check_budget(estimated_cost):
    raise Exception("预算不足")

# 记录消耗
cost_controller.record_cost(actual_cost)
```

### 成本估算

- PlanningAgent：~0.01元/次
- ExecutionAgent：~0.05元/步骤
- QualityAgent：~0.02元/次
- SummaryAgent：~0.01元/次

总成本 ≈ 0.01 + 0.05 × 步骤数 + 0.02 + 0.01

## 错误处理

### 重试机制

- 质量检查失败：自动重试，最多3次
- 网络错误：单步重试，最多3次
- 超时：增加超时时间后重试

### 错误类型

1. **计划生成失败**：提示用户重新描述需求
2. **下载失败**：记录失败步骤，继续执行其他步骤
3. **质量不达标**：触发重试或提示用户手动调整
4. **预算超限**：停止执行，返回已完成部分

## 性能优化

### 并发控制

- 最多同时下载3个资源
- 使用异步IO提升效率
- 限制单个文件大小（10MB）

### 缓存策略

- 计划缓存：内存存储，1小时过期
- 进度缓存：Redis存储，24小时过期
- 内容缓存：避免重复下载相同URL

## 安全考虑

### 输入验证

- 需求描述长度限制：1-500字符
- 下载数量限制：1-20个
- URL白名单：仅允许可信域名

### 权限控制

- 需要登录才能使用
- 知识库权限检查
- 下载频率限制：每用户每小时最多10次
