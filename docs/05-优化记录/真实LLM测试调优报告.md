## LLM 决策质量分析

### 决策理由示例

**Simple 路径决策**:
- "这是一个简单的概念性问答，答案高度确定，不需要规划或复杂推理"
- "如何安装 pip 是非常基础的一个标准操作技能问题，答案高度确定，无需复杂规划"
- "输入长度极短，问题简单，知识库覆盖率为0%，但通过常识可以直接回答"

**Standard 路径决策**:
- "涉及代码分析和优化建议，需要规划和质检"
- "需要实现具体功能（LRU缓存）并考虑线程安全，需要规划和验证"

**Complex 路径决策**:
- "涉及分布式系统架构设计，包括注册、登录、权限管理、会话管理和审计日志等多个模块，需要详细规划、多步骤实施和全面质检"

### 置信度分析

- **Simple 路径**: 平均置信度 **95%**（非常高）
- **Standard 路径**: 平均置信度 **90%**（高）
- **Complex 路径**: 置信度 **95%**（非常高）

**结论**: LLM 对决策非常有信心，且实际准确率验证了这一点。

## 错误分析

### 唯一错误案例

**输入**: "帮我写一个快速排序算法，并解释原理"

**预测**: simple (置信度 95%)  
**期望**: standard  
**实际**: 应该是 standard（需要代码生成 + 解释）

**原因分析**:
1. LLM 可能认为快速排序是常见算法，可以直接生成
2. 没有考虑"解释原理"需要额外的规划和质检

**改进建议**:
- 在提示词中强调"代码生成 + 解释"类任务应选择 standard
- 添加更多示例（few-shot learning）

## 提示词有效性

### 当前提示词结构

```
你是一个任务复杂度分析专家。请分析以下用户请求的复杂度...

用户请求：{user_input}

上下文信息：
- 输入长度: {length} 字符
- 知识库覆盖率: {coverage}%
- 剩余预算: ${budget}

执行路径选项：
1. simple（80%任务）：简单问答、直接检索，成本 $0.10
2. standard（15%任务）：需要规划和质检，成本 $0.50
3. complex（5%任务）：多步骤、需要迭代，成本 $2.00

请按以下 JSON 格式回复：
{
  "path": "simple|standard|complex",
  "confidence": 0.0-1.0,
  "reasoning": "选择理由（一句话）",
  "estimated_cost": 预估成本（美元）,
  "key_factors": ["关键因素1", "关键因素2"]
}
```

### 提示词优势

1. ✅ **清晰的路径定义**：明确说明每个路径的特点和成本
2. ✅ **上下文感知**：提供输入长度、知识库覆盖率、预算等信息
3. ✅ **结构化输出**：JSON 格式易于解析
4. ✅ **置信度要求**：让 LLM 评估自己的决策质量

### 改进空间

1. **添加示例**（Few-shot learning）:
   ```
   示例 1：
   输入："什么是 Python？"
   输出：{"path": "simple", "confidence": 0.95, ...}
   
   示例 2：
   输入："设计一个分布式系统"
   输出：{"path": "complex", "confidence": 0.90, ...}
   ```

2. **强调边界情况**:
   - "代码生成 + 解释" → standard
   - "多个子任务" → standard 或 complex
   - "架构设计" → complex

3. **动态调整**:
   - 根据历史决策准确率调整提示词
   - 收集错误案例，添加到提示词中
